How to read every pattern page

This playbook is a pattern-first curriculum for arrays. Each of the 24 families is dissected with the same anatomy, so once you learn the layout you can navigate any pattern — and any interview story — in the same order.

Patterns, not problems
Interviewers rarely invent new algorithms — they dress up one of ~24 array patterns. Recognising the family is 80% of the solve. Every page names the recognition signals that give the pattern away.
The Best → Better → Optimised ladder
Every solution is shown three times: the brute force you can always reach, the better idea that fixes its bottleneck, and the optimised approach with its proof sketch. In interviews, narrate exactly this climb.
Theory you can actually use
Each family is reduced to its mathematical model — the invariant, recurrence or counting argument that makes it work. If you can state the invariant, you can re-derive the code under pressure.

③ Approach navigation — Best / Better / Optimised

Brute force. State it, code it, then name its bottleneck out loud — “this recomputes the sum for every start index.”

Better. Remove one waste: memoise, precompute, sort. Complexity drops a notch, structure usually survives.

Optimised. The invariant does all the work — each element is touched a bounded number of times, so the whole pass is linear.

Interview soundbite: “Brute force is X, its cost is Y; the waste is Z; removing Z gives the optimal.”
