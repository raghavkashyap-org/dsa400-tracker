01 · The roadmap

How to actually master DSA

Getting good at Data Structures and Algorithms cleared interviews at Amazon, Google and Microsoft for the author of the playbook this page is built on — but thousands of hours were wasted on things that did not help. This is the distilled version: what to learn, in what order, with what resources, and how to never forget it.

The three pillars — and only these

1 · Data structures
How data is organised in memory.
  • Array · String
  • Linked List · Stack · Queue
  • Hash Table
  • Heap · Tree · Trie · Graph
2 · Algorithms
The procedures that operate on them.
  • Sorting · Searching · Binary Search
  • Recursion · Backtracking
  • BFS · DFS · Two Pointers
  • Sliding Window · Divide & Conquer · DP · Greedy
3 · Problem-solving techniques
The pattern-recognition layer.
  • Recognise → map to a known pattern
  • Reason about complexity
  • Invariants · exchange arguments
  • Reason, debug, design, verify — engineering judgement
Scope rule: segment trees and Fenwick trees are rarely asked in coding interviews. In the beginning, focus on the most common topics — breadth first, depth later.

Learn one topic at a time — in this order

Trying to learn multiple topics simultaneously is overwhelming. Start with linear data structures and graduate to the recursive ones.

STAGE 1
Arrays & strings — traversal, in-place ops, prefix sums, hashing
STAGE 2
Linked lists — pointers, fast & slow, in-place reversal
STAGE 3
Stacks & queues — monotonic stacks, queues via lists
STAGE 4
Trees — traversals, BSTs, recursion depth
STAGE 5
Heaps — top-k, streaming extremes
STAGE 6
Graphs — DFS, BFS, shortest paths, union-find
STAGE 7
DP & backtracking — once every earlier stage is fluent
How to start any new topic — six moves
1
Start with the basics
What it is, how it is represented, core operations and their complexities — e.g. insert / delete / search on a BST.
2
Real-world applications
Graphs → GPS routing; heaps → schedulers; hashing → caches. Context makes it stick.
3
Use pen and paper
Draw nodes and pointers, write pseudocode. Visualising beats re-reading.
4
Implement it from scratch
A stack with push / pop / peek on your own — the mechanics stop being magic.
5
Learn the inbuilt library
unordered_map / priority_queue in C++, HashMap / PriorityQueue in Java — use them fluently.
6
Solve 4–5 easy problems
Reading is not learning. Build confidence on the topic before moving on.

How to scale up — and never forget

Solve > theory
Theory matters at the start; the real learning is applying it. More problems, more reinforcement.
Challenge yourself
DSA is like the gym: lifting the same weight daily never makes you stronger. Easy → medium → hard.
Understand, don't memorise
Memorised solutions collapse on unseen problems. Principles transfer.
Think in patterns
Group similar problems, note recurring techniques — that's exactly what the 40 patterns below are.
Repetition is key
Revisit hard problems and re-solve them without looking. That is how knowledge moves to long-term memory.
Create revision lists
LeetCode lists for every problem you failed on first attempt — your personal weak-spot map.
Be consistent
Some topics take weeks. Stuck? Take a break, check hints, read the discussion — then try again.
